# Android Firebase Distribution Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a manual GitHub Actions path that builds a durably signed staging APK and distributes it to a Firebase App Distribution tester group.

**Architecture:** Expo remains the source of Android native configuration. A local Expo config plugin generates an idempotent Gradle signing overlay, while the workflow supplies signing material through the `android-staging` GitHub environment and authenticates to Firebase with GitHub OIDC and Google Workload Identity Federation.

**Tech Stack:** Expo SDK 55 config plugins, TypeScript, Vitest, Gradle/Groovy, GitHub Actions, Google Workload Identity Federation, Firebase CLI 15.24.0.

**Global Constraints:**

- Keep distribution manual-only and staging-only.
- Do not create or modify Firebase, Google Cloud, GitHub environment, secret, or tester configuration.
- Do not add Firebase runtime SDKs or `google-services.json`.
- Do not expose secret values in logs or artifacts.
- Preserve the current local debug build path when release signing is not required.
- Do not push, deploy, or distribute without separate user authorization.
- Keep the committed generated Android scaffold on the development identity.


**Step 3: Implement the minimum config change**

In `apps/mobile/app.config.ts`, add:

```ts
const resolveAndroidVersionCode = () => {
  const rawVersionCode = process.env.ANDROID_VERSION_CODE;
  if (rawVersionCode === undefined) return 1;

  const versionCode = Number(rawVersionCode);
  if (!Number.isInteger(versionCode) || versionCode <= 0) {
    throw new Error("ANDROID_VERSION_CODE must be a positive integer");
  }

  return versionCode;
};
```

Set `android.versionCode` from this function without changing package selection.


```yaml

  cancel-in-progress: false
```

- One Ubuntu job using environment `android-staging`.
- Job environment values mapped from:
  - `vars.GCP_PROJECT_ID`
  - `vars.GCP_WORKLOAD_IDENTITY_PROVIDER`
  - `vars.GCP_SERVICE_ACCOUNT`
  - `vars.FIREBASE_APP_ID_ANDROID_STAGING`

- A first step that checks required names through indirect shell lookup and prints only missing names.
- `actions/checkout@v6`, `pnpm/action-setup@v4`, `actions/setup-node@v6`, and `actions/setup-java@v5` with Temurin 17 and Gradle caching.
- `pnpm install --frozen-lockfile`.
- Base64 decoding to `$RUNNER_TEMP/multica-staging.jks`, publishing only the path through `$GITHUB_ENV`.
- Staging prebuild:

```bash
pnpm -C apps/mobile android:sync:staging
```

- Staging release bundle/build:

```bash
pnpm -C apps/mobile exec dotenv -e .env.staging -- \
  cross-env APP_ENV=staging \
  sh -c 'cd android && ./gradlew assembleRelease --no-daemon'
```

- `actions/upload-artifact@v4` for `app-release.apk`, seven-day retention.
- `google-github-actions/auth@v3` with Workload Identity provider, service account, and project ID.
- A distribution step using `pnpm dlx firebase-tools@15.24.0` and a default release note containing the commit SHA when the manual input is empty.
